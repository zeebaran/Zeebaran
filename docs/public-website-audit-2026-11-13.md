# Zeebaran public website audit

## Scope and architecture

The current working tree contained 156 existing changes at discovery. The audit used that tree and separate local production builds. Git history and production data were preserved.

App Router source discovery and the published catalog API identified 26 concrete pages. These include the home page, Platform, Mission, Hub, Innovation, Impact, Partnerships, Governance, About, Contact, short enquiry, Podcast, Varieties, comparison, eight varieties, and four rootstocks. The production build shows prerendered public editorial routes, generated catalog detail pages, and request-time catalog, comparison, and sitemap routes. Public CMS content uses server caching with 60-second revalidation. Catalog reads use a separate 300-second cache. These are source and build observations. They do not measure Firestore reads or cache hits in production.

## Responsive and functional verification

- Chromium and WebKit each checked all 26 public routes across 62 widths from 320 to 3440 px, including CSS breakpoints and adjacent widths, plus four landscape sizes from 568 × 320 to 1024 × 600. Across 3,432 route, engine, and viewport combinations, there was no document-level horizontal overflow above 1 px. Every route returned HTTP 200 and contained one main heading. The harness captured no uncaught page errors or HTTP responses of 400 or higher in these route loads.
- A rendered-link crawl checked 35 unique same-origin request URLs and found no HTTP errors or missing same-page anchor targets. Back and forward navigation passed. The crawl inventoried 20 external HTTP links. It did not verify delivery to those destinations or cross-route fragment targets exhaustively.
- The final Chromium and WebKit public regression suite had 123 passes, 3 skips, and 0 failures. The skips were two local-inbox cases without an isolated inbox fixture and a duplicate WebKit accessibility run. Four additional Podcast navigation and sketch tests passed. A separate smoke test used the four published episodes and confirmed that selection, search, and clearing filters made zero additional site API requests in both engines. Live YouTube playback was outside that smoke test.
- Lint and the Webpack production build with TypeScript passed. All 231 unit tests passed. The sitemap, robots file, and local Open Graph image each returned HTTP 200 with the expected media type. Firefox could not launch because its temporary browser profile was inaccessible. Enquiry tests used controlled responses without sending real mail. Actual microphone recognition and production integrations require separate verification.
- The matrix measures document overflow and direct rendering. Component-level overlap, touch behavior, and visual design were covered by targeted checks. It is not an exhaustive visual inspection of every interaction at every width.

## Performance measurements

Chromium measurements used fresh browser contexts against local production builds, with three samples per route. Desktop used 1440 × 1000 unthrottled. Simulated mobile used 390 × 844, 4× CPU slowdown, 100 ms RTT and 1.6 Mbps download. The server cache was not reset between samples. Other verification work ran on the same host. These are lab observations and have no field percentile interpretation.

| Route     | Desktop LCP | Mobile LCP | Mobile FCP | Mobile blocking time observed | Mobile layout-shift sum |
| --------- | ----------: | ---------: | ---------: | ----------------------------: | ----------------------: |
| Home      |      516 ms |   1,500 ms |     912 ms |                         26 ms |                   <0.01 |
| Platform  |       68 ms |   1,660 ms |     832 ms |                         12 ms |                   <0.01 |
| Varieties |      336 ms |   1,100 ms |   1,100 ms |                         30 ms |                       0 |
| Mission   |      360 ms |   1,880 ms |     900 ms |                         25 ms |                    0.04 |
| Podcast   |      464 ms |   2,924 ms |     832 ms |                         26 ms |                   <0.01 |
| Contact   |       88 ms |   1,652 ms |     812 ms |                         18 ms |                    0.01 |

- Median TTFB by route was 2–8 ms locally on desktop and 100–101 ms with simulated mobile networking. Observed desktop script transfer was approximately 378–388 KiB over the measurement window. Mobile transfers are partial because scripts could still be loading at the end of that window.
- All 24 sampled route clicks were client-side transitions. The reduced-motion production sample reached the destination heading in 46–95 ms. Catalog transitions fetched server-rendered data in 16–25 ms locally. Prefetched editorial payloads completed in 2–8 ms.
- A separate desktop comparison measured Platform, Varieties and Podcast headings mounting in 62–87 ms in production and 92–209 ms in development with motion enabled. The production heading animations settled in 1,233–1,385 ms from the click. The equivalent reduced-motion sample mounted in 50–75 ms and settled in 52–102 ms. These single runs isolate the visible animation duration from route mounting. They do not measure a cold deployed request or reproduce every report of lag.
- Layout shift is the sum observed during sampling, not field CLS. INP, production Core Web Vitals, long-session memory behavior, and actual Firestore operation volume were not measured.

## Checkpoint verdict

The local public build passed broad responsive checks. Navigation mounted quickly in the tested conditions, and the existing entrance animations explain a measurable portion of the perceived delay. The comparison URL failure and intermittent test assertion have targeted corrections. Production readiness for the full application remains open pending deployed performance, authenticated admin workflows, Firebase security and operations, and cross-system verification.
